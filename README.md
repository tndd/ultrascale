# UltraScale

> このブランチは画質調整の試験版です。通常利用向けの正式版は [main](https://github.com/tndd/ultrascale/tree/main) にあります。画面収録を使うフィルタ、シャープネス、低レイヤーの調査、検証ツールは試験中であり、実機のクリック動作とブラウザ文字の画質改善は未確認です。正式版には取り込んでいません。

3440 × 1440の外部モニタで、文字・UIの大きさを100〜200%の範囲で1%刻みに選ぶmacOSアプリです。縦横比を維持し、選んだ見かけの解像度の2倍で描画する仮想HiDPI画面を外部モニタへ表示します。通常モードはミラー表示、試験的な画質調整モードは取り込んだ画面をMetalで描画します。整数ピクセルへの丸めにより各辺に最大0.5ピクセルの差があります。

## 使い方

1. 下記の手順でビルドし、`build/Applications.noindex/UltraScale.app` を開きます。必要ならFinderで「アプリケーション」へコピーできます。
2. 3440 × 1440の外部モニタを接続し、対象を選びます。
3. スライダーで倍率を選び、「HiDPIを適用」を押します。
4. 適用した設定はそのまま維持されます。15秒以内なら「変更前の表示に戻す」で取り消せます。直前にHiDPIを使っていた場合はその倍率へ、初めて適用した場合は通常表示へ戻ります。取り消しボタンは常に表示され、適用後15秒間だけ押せます。15秒経過すると無効になりますが、表示は変わりません。
5. 15秒経過後にHiDPI自体を解除するには、メニューバーの「元の表示に戻す」を使うか、アプリを終了します。

ウインドウを閉じてもHiDPI表示は継続します。メニューバーのディスプレイアイコンから再表示・解除・終了できます。画面下部の「メニューバーにアイコンを表示」でアイコンを非表示にでき、選択は次回起動時にも引き継ぎます。非表示のときもDockやLaunchpadから画面を再表示し、同じチェック項目でアイコンを戻せます。スリープ時は解除します。スリープ復帰後や再接続後は手動で適用してください。既存のミラーリングがある場合は先にシステム設定で解除してください。

未接続時にも倍率と見かけの解像度を確認できますが、適用は無効になります。内蔵画面へ適用する機能はありません。

## 画質調整（試験）

「画質調整モード」をチェックして「HiDPIを適用」すると、以下を比較できます。チェックを外して再適用すると通常のミラー表示に戻ります。

- 縮小フィルタ: バイリニア、バイキュービック、Lanczos。
- シャープネス: 0〜100%。0は輪郭補正なし、初期値は25%。縮小した画像の輝度を補正します。強くしすぎると文字の周囲に縁取りが出る場合があります。
- 画質調整中はフィルタとシャープネスの変更が即座に反映されます。モードと選択値は次回起動にも引き継ぎます。

macOSの「プライバシーとセキュリティ」でUltraScaleに画面収録とアクセシビリティの許可が必要です。許可がなければ既存の表示を維持して案内を出します。許可後はアプリを再起動してください。

画質調整モードでは実モニタをネイティブ解像度に保ち、仮想デスクトップをScreenCaptureKitで取り込んでCore Image / Metalで縮小・輪郭補正します。取得するのは仮想画面だけで、音声は取り込みません。画像をファイルへ保存したり外部へ送信したりしません。仮想画面へのウインドウ移動にはアクセシビリティAPIを使います。終了・解除時は配置と通常表示を復元します。一部のアプリが移動を拒否するウインドウは自動移動できない場合があります。

通常のミラー表示よりGPU負荷と遅延が加わります。フィルタは物理ピクセルを増やす機能ではなく、鮮明さの改善を保証するものではありません。同じ文字を見ながら比較してください。映像を取得・描画できない場合は通常表示へ戻します。

## アイコン

標準は緑のスクリーン版（バーなし）です。予備として青いスクリーン＋角丸スライダーもアプリに収録しています。「UltraScale → Dockアイコン → 青／緑」から起動中のDockアイコンを切り替えられ、選択は次回起動時にも引き継ぎます。Finderに表示するアプリファイルのアイコンは緑です。

原画と透過素材は `Assets/Icons/` に保存しています。輪郭の切り抜きと各サイズへの変換はコードで再現できます。手順は [アイコン素材の説明](Assets/Icons/README.md) を参照してください。

| 倍率 | 見かけの解像度 | 内部の描画解像度 |
| --- | --- | --- |
| 100% | 3440 × 1440 | 6880 × 2880 |
| 125% | 2752 × 1152 | 5504 × 2304 |
| 150% | 2293 × 960 | 4586 × 1920 |
| 200% | 1720 × 720 | 3440 × 1440 |

## 対応範囲と制限

- 同梱バイナリはApple Silicon向けです。今回の動作検証環境はMacBook Air M4 / macOS 15.8.1です。
- 仮想画面は60 Hz・SDRです。HDR、可変リフレッシュレート、高リフレッシュレートは対象に含めません。
- 倍率の変更はモード切り替えです。ドラッグ中にデスクトップが連続アニメーションするものではなく、「適用」で切り替わります。画面の瞬断やウインドウの移動が起こる可能性があります。
- HiDPIは高解像度で描画してから縮小する方式です。モニタ自体の物理画素数は増えません。画質・負荷はモニタや接続構成によって異なります。
- 非公開の `CGVirtualDisplay` APIを使います。macOS更新後の互換性は保証されません。利用できない場合はエラーを表示します。
- 設定変更はアプリの動作中だけのCore Graphics設定です。システムファイル、ディスプレイのオーバーライド、SIP、ログイン項目は変更しません。通常モードは画面を取り込みません。画質調整モードは仮想画面をメモリ内で処理します。
- ローカルビルド用のアドホック署名です。Developer IDによる署名・公証は行っていません。

## 検証

検証内容と未検証事項は `VALIDATION.md` に記録しています。実際の3440 × 1440モニタで、追加確認なしで15秒を過ぎても125%を維持すること、適用直後の通常表示への取り消し、150%への変更を取り消して直前の125%へ戻ることを検証しました。画質の目視確認・抜き差し・スリープ復帰は未検証です。仮想画面での検証は実モニタでの検証を代替しません。

## ビルドとテスト

外部ライブラリやXcodeプロジェクトは不要です。AppleのCommand Line Toolsが必要です。

```bash
git clone https://github.com/tndd/ultrascale.git
cd ultrascale
./build.sh
./install.sh
open /Applications/UltraScale.app
./test.sh
```

ビルド結果は標準で、リポジトリ内の `build/Applications.noindex/UltraScale.app` に出力されます。`./build.sh /任意の出力先/UltraScale.app` で変更できます。

実行中のアプリへ直接ビルドすることは禁止しています。実行中のコードとディスク上の署名が異なると、設定画面で許可済みでも権限が認識されないためです。更新は`build/`へビルドし、UltraScaleを終了してからアプリを置き換え、Finderまたは`open /Applications/UltraScale.app`で起動し直してください。

標準のアドホック署名では更新によりアプリの識別情報が変わるため、画面収録・アクセシビリティの再許可が必要になる場合があります。設定画面の「終了して再度開く」まで完了してください。手元に有効なコード署名証明書がある場合は、同じ証明書を継続使用するため`ULTRASCALE_SIGNING_IDENTITY`にその名前を指定できます。証明書の作成・取得はこのスクリプトでは行いません。

`install.sh`は既存版と更新候補の署名識別条件を比較し、違う場合はアプリを終了・置換する前に中止します。これにより、開発用ビルドで既存の許可を繰り返し無効にする更新を防ぎます。同じ証明書で継続署名することが基本です。署名を切り替えると決めた初回だけ`./install.sh --replace-signing-identity`で明示的に更新できます。この指定はmacOSの許可を付与するものではありません。

```sh
ULTRASCALE_SIGNING_IDENTITY='Developer ID Application: 証明書の名前' ./build.sh
```

実際のWindowServer APIで仮想画面・ミラー・復元を検証する場合は次を実行します。一時的な仮想画面を作成するため、テスト中はデスクトップ配置が変わる場合があります。

```bash
./test.sh --virtual
```

テスト用バイナリとUI画像はGit管理外の `build/` に出力します。アプリのUIテストはAppKitの実コントロールへアクションを送信し、ウインドウ内容を描画・検査します。ユーザーの実クリックや実モニタの目視検証とは区別しています。下記のHTML比較画面は、別途Playwrightで操作検証しています。

### 外部モニタなしの画質検証

macOS 14以降・Metal対応GPUで、画面収録やアクセシビリティの権限を使わずに実行できます。現在のディスプレイ設定は変更しません。

```sh
./verify-quality.sh
open build/quality-lab/index.html
# 第2引数は100〜200の整数。省略時は120。
./verify-quality.sh build/quality-lab-150 150
```

アプリと同じ`USFilteredImage`に、2倍描画した日本語・英数字・細線を入力し、3440×1440へ出力します。バイリニア、バイキュービック、Lanczos、Lanczos＋シャープネス25/75をA/B比較できます。左右のスクロール連動、補間なしの4倍表示、全画面PNG、数値・ハッシュを含むJSONを用意しています。HTMLはサーバーなしで開けます。

自動判定は「設定が画素に反映されたか」「寸法・不透明度が正しいか」「測定系が故意のぼけ・縁取り・無変化を検出できるか」です。200%の1:1出力では縮小方式による差がないことを確認します。終了コードは成功0、検証失敗1、引数・環境・保存失敗2です。意図的にシャープネスを無効化する次の試験は、終了コード1になるのが期待値です。

```sh
./verify-quality.sh build/quality-lab-noop 120 --inject-noop
```

見やすさは自動合格にしません。WindowServerの合成、実画面への提示、入力操作、映像接続とパネルも別の検証です。ブラウザの1 CSS pxは物理モニタの1画素を保証しません。

比較画面を変更した場合の操作テスト（このテストだけNode.jsが必要）：

```sh
./verify-quality.sh
npm ci
npx playwright install chromium
npm run test:report
```
