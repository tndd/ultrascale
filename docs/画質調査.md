# 画質調査 — 2026-10-15

目的は文字・細線を含む画面の見やすさを改善すること。画素差やAPIの成功を最終成果と扱わない。

## 実機で確認できたこと

- macOS 15.8.1、Apple Silicon、Mi 3440×1440。通常125%は論理2752×1152、描画5504×2304から縮小する。調査冒頭に通常125%を再適用できた。
- 試験版の画質調整は権限チェックで失敗。実画面が鮮明になったという証拠はまだない。画面収録とアクセシビリティの不足を分けて表示する修正を追加した。
- 途中でMacがロック状態になった。WindowServerにはUltraScaleのウインドウがあったが、操作先はloginwindowの「ログイン」画面だった。AXウインドウ数0をアプリの起動失敗と混同しない。
- `/Applications/UltraScale.app` は配布済み0.1.3へ差し戻した。元のZIPとのSHA-256一致を確認：`0121d5a30924a8d1166efb3ec200ffcbb0adcdbfc455165eff18b2f8fd6ad577`。
- 差し戻し後の125%再適用はロック解除待ち。最後の状態は通常3440×1440、仮想画面なし。復旧完了とは扱わない。

## 下位レイヤーの調査

このMacのIOMobileFramebuffer接続ライブラリを`dyld_info -exports`と`-disassemble`で調べた。カーネルドライバー全体やDCPファームウェアの解析完了を意味しない。対象UUIDは `41CED59B-B76F-31FB-8785-3E39CA6AAE9E`。

- IOMobileFramebufferShimへ`IOMobileFramebufferOpen`で接続し、`IOMobileFramebufferGetDigitalOutMode`を実行。両戻り値0で、色ID81・タイミングID44を取得できた。
- APIの出力引数順は色ID、タイミングID。初回は逆と仮定していたため、IORegistryのIDと照合して修正した。
- 色81の登録値：Depth=10、PixelEncoding=3、DynamicRange=1、Colorimetry=1。タイミング44：Active=3440×1440、約60Hz、IsOverscanned=false。
- 色74はDepth=8、PixelEncoding=0、DynamicRange=0、Colorimetry=10で、次の比較候補。同名enumが別APIにあっても数値の意味を流用して断定しない。
- GetDigitalOutModeは内部関数へ0x40と44バイトの応答領域を渡し、成功時に2整数を返す。SetDigitalOutModeは別の関数ポインターへ転送する。変更APIは未実行。
- SkyLightに出力モード変更とウインドウ用Core Imageフィルタのシンボルがある。存在だけで全画面の縮小や文字描画へ適用可能とは判断できない。
- IOAVServiceCopyDiagnosticsStringはこのOSでは即座にNULLを返す実装。診断文字列による確認はできなかった。

再現する読み取り専用ツール（映像取得・出力変更・プロパティ書き込みなし）：

```sh
xcrun clang -fobjc-arc -Wall -Wextra -Werror -framework Foundation -framework IOKit scripts/display-diagnostics.m -o build/display-diagnostics
./build/display-diagnostics
```

## 画像処理の比較

日本語・英数字・色付き文字・細線を2倍描画し、125%相当の物理寸法へ縮小する。直接同じ物理寸法で描画した参考、3種類の縮小、Lanczos＋強度25/75を比較した。

```sh
xcrun clang -fobjc-arc -Wall -Wextra -Werror -framework Cocoa -framework CoreImage -I Sources Sources/ImagePipeline.m scripts/quality-comparison.m -o build/quality-comparison
./build/quality-comparison build/quality-comparison.png
```

強度75では文字と細線が濃くなる一方、輪郭の縁取りが増える。元の形や情報が復元されたという意味ではない。等倍で比較する。これは処理関数の出力比較であり、実機ストリームの提示やパネル上の最終画質の検証にはならない。

## 残る検証

1. ロック解除後に0.1.3で125%を再適用し、15秒後も倍率・入力が維持されることを確認。
2. 最新試験版自身の権限認識を確認。アドホック署名はビルドでcdhashが変わるため再許可が必要になる可能性があるが、今回の原因とは断定していない。
3. 出力変更APIの引数と復元方法を確認したうえで、元の出力モードを保存してRGB候補を比較。文字・色付き1ピクセル線を実画面で評価する。現時点では未実行。
4. ストリームの実機テストで表示用GPUテクスチャ、物理画面への提示、上下方向、クリック、15秒以上の維持、終了復元を確認。
5. 同じ倍率・素材・出力形式で通常ミラーと各フィルタを比較。縁取り・色付き縁・遅延が増える設定を改善扱いしない。

## 判断と一次資料

WindowsのDirectWriteは文字描画段階でClearTypeやグレースケール描画を扱う。完成画面を縮小・シャープ化する処理と同じではない。出力形式、縮小、文字描画方式を切り分ける。Windowsに近い見え方が実現可能かは調べる価値があるが、現段階では必ず実現可能とも不可能とも断定しない。
